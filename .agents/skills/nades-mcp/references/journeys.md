# Real MCP journey index

The repository's executable acceptance journey is `just verify-mcp`. It builds release binaries, runs the real stdio MCP client and app, snapshots binary hashes under a fresh `.runs/mcp-*`, checks each structured result against its advertised schema and records actual results and images. It APFS-clones the configured database, injects the clone into its clients, and removes the clone after test-owned windows exit. Inspect `results.json`, `environment.json`, `tools.jsonl` and `database-cleanup.json`; the command's exit status alone does not replace reviewing a failed or pending criterion.

The full verifier requires a macOS desktop session with a usable GPU, de_cache/de_mirage/de_dust2 packs, an available database containing a Dust II A-site Molotov and smoke, FFmpeg with libx264, and ffprobe. Missing prerequisites are unavailable coverage, not a pass. The verifier pins private binary copies and scratch state. Concurrent sessions may compete for the GPU or occlude windows; each verification run has isolated evidence and owned PIDs. Compare recorded hashes with the tested artifact and report contention or occlusion honestly. The user's database and another session's processes must not be modified or terminated.

| Journey | Entry and actions | Observable success |
| --- | --- | --- |
| Discover and control | `app_status`, `maps_list`, `app_start`, `camera_set`, `frame_capture`, `app_stop` | Real map presented; actual camera, instance, revision and frame returned; PNG decodes; stop closes only the owned child. |
| Change maps and recover | `map_open` to a second pack, invalid map, stale ID, child failure, `diagnostics_get` | New map has new identity on restart; invalid preflight preserves the old view; stale IDs and failed children are reported honestly; restart recovers. |
| Headless map | `view_render` cold and while a stable live scene exists | Requested PNG dimensions and provenance; matching live/headless view within the documented tolerance; live state unchanged; worker and temporary output cleaned. |
| Recorded grenade video | `lineups_list`, `video_render`, `video_status`, `video_cancel` | Recorded Molotov produces a decodable H.264 MP4 with expected frames; smoke renders with the live view unchanged; busy, invalid data, absent encoder, cancellation and disconnect are explicit and clean owned processes and partial files. Inspect decoded frames and use `ffprobe`; byte-identical video is not required. |
| Handoff and isolation | Start a ready window, disconnect, use a second MCP session | Ready window survives disconnect and a new server cannot adopt or stop it. Automated verification confirms survival/isolation; normal movement and quit after handoff are a separate manual desktop journey. |

For the handoff's human-interaction check and the retained-database cleanup procedure, follow [verify-mcp](../../verify-mcp/SKILL.md). `--keep-handoff` intentionally leaves an owned window and database clone alive; do not claim that the normal automatic cleanup occurred for it. Missing UI automation or an occluded window is a coverage gap or retryable failure, not proof of movement. Game reference images and their derivatives remain in the neighboring project's `.verify-runs/`.
